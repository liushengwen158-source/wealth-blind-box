# 财富盲盒 · 开发分工

## 一、活动概述

“财富盲盒”是一场单场、单人参赛的模拟投资比赛。比赛由若干历史事件回合组成，每个回合对应一段真实历史行情，选手用虚拟资金在该时段的真实走势中交易，回合时长由管理员配置。

每回合结束时，系统强制平仓并结算本回合收益，资金带入下一回合，最终按累计收益排名。比赛配套盲盒机制和所有人共用的实时排行榜；管理员可通过后台配置赛制、控制比赛进程、发布新闻并导出成绩。

活动目的是在不涉及真实资金的前提下，让参与者体验真实交易规则和历史市场情境。

## 二、技术栈

| 层次 | 选型 | 用途 |
|---|---|---|
| 前端 | Vue 3 + Vite + Element Plus + ECharts | 选手端、管理员后台、排行榜页面；Element Plus 提供表单和表格，ECharts 绘制 K 线与资产曲线 |
| 后端 | Python 3.11 + FastAPI | 提供 REST 接口与 WebSocket，自动生成接口文档 |
| 数据库 | SQLite（WAL 模式） | 单机零配置，满足单场规模；后续可替换为 PostgreSQL |
| 实时通信 | FastAPI WebSocket + 内存广播 | 推送行情、排名和事件切换通知 |
| 行情数据 | 活动前离线下载，保存为本地 CSV | 活动期间不依赖外网，避免接口限流 |
| 部署 | Docker Compose（由活动负责人执行） | 一键启动前后端服务 |
| 开发方式 | AI 辅助开发 + 接口契约先行 | 支持 5 个分支并行开发 |

> 后端需以单进程运行，实时状态保存在内存中，不要开启多个 worker。

## 三、核心规则

1. **回合与时长**：比赛总时长、每回合时长由管理员设置；回合数 = 总时长 ÷ 每回合时长，除不尽时最后一回合按剩余时间截断。
2. **强制平仓**：每回合结束时，系统按最后成交价平掉全部持仓，强制平仓默认免收手续费；平仓后结算本回合收益，资金带入下一回合。
3. **交易规则**：遵循 T+1、涨跌停、整手交易、停牌不可交易；手续费包含佣金、印花税和过户费。
4. **T+1 可玩性**：每个回合至少覆盖 2 个模拟交易日；若某事件只有 1 个交易日的数据，则该回合关闭 T+1 限制并在页面提示。
5. **公平性**：所有选手共享同一事件顺序和同一行情时间线，事件顺序在开赛时一次性确定。
6. **排名**：按累计收益率排序；并列时依次比较最大回撤、交易次数。
7. **盲盒**：开赛时抽取一次，效果持续整场；卡片效果不得依赖某个具体事件的股票池。
8. **新闻**：只播报真实历史摘要，统一标注“历史重演，仅用于教学”，新闻不改变行情。

## 四、五个分支

### 1. 分支一：历史事件 + 行情回放

主责（后端）：
建立历史事件池，每个事件对应一段真实历史时期，准备该时期的真实行情数据和新闻摘要。
实现行情回放：按管理员设置的回合时长播放，支持暂停、变速、跳过；提供事件列表、股票行情、K 线接口，并通过 WebSocket 推送。

**事件池必须使用真实历史数据，不得编造。**
每个事件需注明真实发生时间、数据来源、对应指数和个股，且只选择当时已经上市的股票；行情应与真实走势一致，早期年份缺少分钟数据时注明只能按日线回放。

副责（前端）：
实现行情图表组件（分时图、K 线），供分支三直接复用。

专项：
事件数据质量，确保每个事件的数据真实、完整、可查。优先交付 2 个完整事件用于联调，再补齐事件池。

### 2. 分支二：交易 + 赛制 + 结算

主责（后端）：
实现账户、持仓、下单、撤单、手续费、T+1、涨跌停和整手交易。
实现回合机制：按管理员设置的回合时长推进，到点切换事件；每回合结束强制平仓、结算收益，并将资金带入下一回合。
实现随机抽取事件和盲盒逻辑。

副责（前端）：
实现下单面板，包括价格、数量、可买可卖提示、手续费预估和二次确认。

专项：
交易规则正确性，编写对账测试，确保余额、持仓和手续费计算准确。

### 3. 分支三：选手端

主责（前端）：
实现选手端整体框架和页面，包括登录、比赛大厅、交易大厅、持仓/委托/成交、盲盒、新闻和资产曲线。
比赛大厅需显示当前事件、本回合剩余时间和累计资产，并支持手机适配与断线重连。

副责（后端）：
实现登录、用户信息和选手席位相关接口。

专项：
统一整体交互体验与页面风格，其他分支的页面均参照这套风格。

### 4. 分支四：实时排行榜

主责（后端 + 前端）：
实时计算累计收益排名，通过 WebSocket 推送给所有选手；实现独立的公用排行榜页面，所有人查看同一份榜单。

副责：
对排行榜和行情推送进行性能测试，确保现场数十人同时在线时流畅运行。

专项：
实时推送与性能优化。

### 5. 分支五：管理员后台

主责（前端）：
实现管理员后台页面，包括登录、赛制配置（比赛时长、每回合时长、事件池、初始资金、手续费等）、比赛控制、新闻管理和成绩导出。

副责（后端）：
实现管理员账号、配置与控制接口、导出接口。

专项：
搭建项目骨架、接口文档和 Mock 数据，确保其他分支第一天即可开工。

## 五、部署说明

部署到服务器由活动负责人完成，不属于 5 个分支的工作。
各分支只需保证本地可启动、能按接口文档跑通；负责人负责整合前后端、配置服务器，并在活动当天完成启动。

## 六、协作约定

- 每人至少完成 1 个后端接口和 1 个前端页面。
- 每人编写 1 个可运行的自测，并为另一个人的模块做 1 次验收。
- 事件池数据必须真实可查，不得编造走势；所有数据仅限社团内部教学使用，不对外分发。
- 目录所有权：只修改自己的文件夹，跨目录修改需先沟通。
- 接口先行：第一天确定接口，后续变更需全员同意。
- 每天同步主分支，合并前由另一人检查。

## 七、风险与应对

| 风险 | 应对 |
|---|---|
| 历史数据缺失或精度不足 | 事件池标注数据精度；缺少分钟数据时按日线回放；提前准备至少 2 个可完整演示的事件 |
| 事件数据不真实 | 每个事件记录数据来源与时间范围，并与公开行情抽查比对 |
| 回合切换导致资产异常 | 强制平仓以最后成交价结算，禁止持仓跨回合 |
| 单进程并发压力 | 使用 SQLite WAL，避免长事务；赛前按现场人数做并发测试 |
| 后台配置错误 | 保存配置时校验总时长、回合时长、初始资金等参数是否合法 |
| 前后端接口不一致 | 第一天冻结接口文档，前端先用 Mock 开发 |
| 分支合并冲突 | 执行目录所有权，公共文件由指定人员维护 |
